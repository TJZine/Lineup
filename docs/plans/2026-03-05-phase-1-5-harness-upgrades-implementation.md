# Phase 1.5 Harness Upgrades Implementation Plan

> **For Codex or Claude:** Use the current repo workflow stack exactly as defined by `agents.md`, `docs/agentic/document-map.md`, and `docs/AGENTIC_DEV_WORKFLOW.md`. This plan is written for a fresh session with no carried context.

**Goal:** Complete the next harness upgrades that are still missing after the control-plane bootstrap: a repo-level plan-authoring standard, a tracked eval harness definition, a 12-prompt starter set sourced from real Lineup work, a local-only manual baseline protocol, and a recurring doc-gardening loop.

**Architecture:** Keep the control plane small. Do not create another general workflow doc. The run-bundle split, archive split, and local-only execution-artifact policy already exist and must be reused, not redesigned. New work in this plan must strengthen the current control plane rather than adding parallel surfaces.

**Tech Stack:** Markdown documentation, Codanna MCP discovery tools, `npm run verify:docs`, repo-local skills in `.codex/skills/`, local Antigravity mirrors generated by `scripts/sync_agent_skills.sh`.

## Execution Rules

This plan is intentionally zero-decision-point.

Execute it exactly as written unless:

- a referenced file no longer exists
- the repo topology has changed
- the current tracked docs contradict the plan

If any of those is true:

1. Stop.
2. Update this plan first.
3. Re-run `npm run verify:docs`.
4. Then continue.

Do not continue through contradictions “because the intent is obvious.”

Do not continue into Task 1 with a failing docs baseline.

## Locked Decisions

These are not open for debate during implementation:

- The run-bundle standard under `docs/runs/` is already established. Reuse it; do not redesign it.
- The active-plan vs archived-plan split is already established. Reuse it; do not collapse it.
- Eval prompt definitions are tracked.
- Eval baseline outputs are local-only by default and must not be committed unless explicitly promoted later.
- The imported Priority 2 corpus has already been curated into `docs/agentic/historical-plan-corpus-review.md`. Use that tracked review, not the raw local import folder, as the source-of-truth input.
- Build exactly 12 starter eval prompts.
- Use real Lineup work as prompt source material before inventing synthetic prompts.
- Keep Codanna mandatory for discovery on eval-worthy or architecture-affecting tasks.
- Do not add a repo-local `CODEX.md`.
- Do not add directory-local override docs in this phase.

## Non-Goals

- Do not re-open the control-plane bootstrap.
- Do not add new generic skills.
- Do not commit local run artifacts or local baseline outputs.
- Do not create another general workflow handbook.
- Do not automate a full eval runner yet.

## Desired End State

At the end of this plan:

- serious implementation plans follow one repo standard
- the standard is grounded in real historical Lineup work, not generic theory
- the repo has a tracked eval harness definition
- the first 12 prompts are sourced from real cleanup work plus deliberate shortcut-pressure traps
- the first manual baseline protocol is defined without polluting Git with local score dumps
- the doc-gardening loop is explicit and recurring

**Files:**

**Step 1: Write `docs/agentic/plan-authoring-standard.md`**

Use these exact sections:

```md
# Plan Authoring Standard

## When This Applies

## Required Structure

## Fresh-Session Rules

## Discovery And Evidence Rules

## Invariants And Scope Rules

## Verification And Rollback Rules

## Anti-Patterns To Avoid
```

Required content:

- `When This Applies`
  - serious implementation plans
  - architecture-affecting work
  - multi-session or high-risk tasks
- `Required Structure`
  - goal
  - non-goals
  - parent-priority or parent-architecture alignment
  - required reading
  - required skills
  - Codanna discovery
  - impact snapshot
  - files in scope
  - files out of scope
  - invariants/preservation contracts where relevant
  - verification commands
  - rollback notes
  - commit checkpoints
- `Fresh-Session Rules`
  - require a freshness gate
  - forbid continuing through contradicted assumptions
- `Discovery And Evidence Rules`
  - require `semantic_search_with_context`
  - require `search_documents` when repo docs matter
  - require `analyze_impact` before risky/shared edits
  - require logging the fallback when Codanna is insufficient
- `Invariants And Scope Rules`
  - require explicit in-scope and out-of-scope lists
  - require anti-slop constraints
  - require preservation contracts for UI/runtime refactors
- `Verification And Rollback Rules`
  - require exact commands and expected results
  - require rollback guidance for high-risk work
- `Anti-Patterns To Avoid`
  - stale repo names
  - absolute local paths
  - obsolete workflow names
  - brittle line-number anchoring without freshness guards
  - committing local-only artifacts
